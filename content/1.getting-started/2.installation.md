# Dynalink API

The Dynalink API allows you to programmatically create, manage, and use smart links across platforms, supporting deep links, store redirects, web fallbacks, campaign attribution, and social media previews.

---

## Authentication

Every request requires a **Project Key** via the `x-project-key` header.

```http
x-project-key: YOUR_PROJECT_KEY
```

### Obtaining a Project Key
1. Log in to [Dynalink Admin](https://admin.dynalink.app)
2. Create or open a project
3. Copy the generated project key

### Security Best Practices
- Store your key securely using environment variables
- Never expose your key in client-side code or public repositories

```javascript
fetch('https://dynalink.app/api/endpoint', {
  headers: {
    'x-project-key': 'your_project_key_here',
    'Content-Type': 'application/json'
  }
})
```

## Links

### Create a Link

```http
POST https://dynalink.app/api/links
```

#### Request Body

| Parameter              | Type    | Required | Description                                                      |
|------------------------|---------|----------|------------------------------------------------------------------|
| `actual_url`           | string  | Yes      | The destination URL                                              |
| `name`                 | string  | No       | Human-readable label for the link                                |
| `campaign_id`          | integer | No       | ID of the campaign to associate this link with                   |
| `ios_url`              | string  | No       | Direct link to iOS App Store                                     |
| `android_url`          | string  | No       | Direct link to Google Play Store                                 |
| `ios_bundle_id`        | string  | No       | iOS Bundle ID — auto-resolves the App Store URL via iTunes API   |
| `android_package_name` | string  | No       | Android package name — auto-resolves the Play Store URL          |
| `fallback_url`         | string  | No       | Fallback URL if no store or deep link applies                    |
| `is_deeplink`          | boolean | No       | Whether the link should open the app via deep link               |
| `should_open_store`    | boolean | No       | Whether to open the store if the app is not installed            |
| `social_title`         | string  | No       | Title for social media link previews                             |
| `social_description`   | string  | No       | Description for social media link previews (max 160 chars)       |
| `social_image`         | string  | No       | Image URL for social media link previews                         |

#### Example

```bash
curl -X POST https://dynalink.app/api/links \
  -H "Content-Type: application/json" \
  -H "x-project-key: YOUR_PROJECT_KEY" \
  -d '{
    "actual_url": "https://yourapp.io?screen=offer&id=99",
    "name": "Summer promo deep link",
    "campaign_id": 4,
    "is_deeplink": true,
    "should_open_store": true,
    "ios_bundle_id": "com.yourapp.ios",
    "android_package_name": "com.yourapp.android",
    "fallback_url": "https://yourapp.io"
  }'
```

#### Response

```json
{
  "id": 42,
  "code": "SUMR99",
  "actual_url": "https://yourapp.io?screen=offer&id=99",
  "name": "Summer promo deep link",
  "campaign_id": 4,
  "fallback_url": "https://yourapp.io",
  "ios_url": "https://apps.apple.com/app/id123456789",
  "android_url": "https://play.google.com/store/apps/details?id=com.yourapp.android",
  "is_deeplink": true,
  "should_open_store": true,
  "clicked_count": 0,
  "project_id": "9dfbcaf4-052b-4093-92fb-5781a2baa243",
  "created_at": "2026-05-21T10:00:00.000000Z",
  "updated_at": "2026-05-21T10:00:00.000000Z"
}
```

### Link Types

#### Standard Web Link
```json
{ "actual_url": "https://yourapp.io", "fallback_url": "https://yourapp.io" }
```

#### Deep Link with Store Fallback
```json
{
  "actual_url": "yourapp://screen/offer?id=99",
  "is_deeplink": true,
  "should_open_store": true,
  "ios_bundle_id": "com.yourapp.ios",
  "android_package_name": "com.yourapp.android",
  "fallback_url": "https://yourapp.io"
}
```

#### Social Preview Enabled
```json
{
  "actual_url": "https://yourapp.io/product/99",
  "social_title": "Check this out",
  "social_description": "Exclusive summer deal — 40% off",
  "social_image": "https://yourapp.io/og-summer.jpg"
}
```

## Campaigns

Campaigns group links together and add UTM parameters automatically to every attributed click.

### Create a Campaign

```http
POST https://dynalink.app/api/campaigns
```

| Parameter      | Type   | Required | Description                                          |
|----------------|--------|----------|------------------------------------------------------|
| `name`         | string | Yes      | Campaign display name                                |
| `status`       | string | No       | `draft` (default), `active`, `paused`, `archived`    |
| `description`  | string | No       | Internal notes                                       |
| `utm_source`   | string | No       | UTM source (e.g. `google`, `newsletter`)             |
| `utm_medium`   | string | No       | UTM medium (e.g. `cpc`, `email`)                     |
| `utm_campaign` | string | No       | UTM campaign slug                                    |
| `utm_term`     | string | No       | UTM term (paid search keywords)                      |
| `utm_content`  | string | No       | UTM content (A/B variant identifier)                 |
| `start_date`   | string | No       | ISO 8601 date (`YYYY-MM-DD`)                         |
| `end_date`     | string | No       | ISO 8601 date (`YYYY-MM-DD`)                         |

```bash
curl -X POST https://dynalink.app/api/campaigns \
  -H "Content-Type: application/json" \
  -H "x-project-key: YOUR_PROJECT_KEY" \
  -d '{
    "name": "Summer 2026",
    "status": "active",
    "utm_source": "google",
    "utm_medium": "cpc",
    "utm_campaign": "summer_2026"
  }'
```

### List Campaigns

```http
GET https://dynalink.app/api/campaigns
```

Query params: `search`, `status`, `per_page` (default 15), `page`.

### Get Campaign Stats

```http
GET https://dynalink.app/api/campaigns/{id}/stats?days=30
```

Returns click counts per day, top links, and aggregate totals for the given period (default 30 days, max 365).

```json
{
  "total_links": 5,
  "total_clicks": 230,
  "clicks_per_day": [
    { "date": "2026-05-01", "count": 12 },
    { "date": "2026-05-02", "count": 18 }
  ],
  "top_links": [
    { "id": 42, "code": "SUMR99", "name": "Summer promo", "actual_url": "...", "clicked_count": 95 }
  ]
}
```

## Clicks opened straight by the OS

When Android App Links or iOS Universal Links are verified, the OS hands the link
to the app without loading the DynaLink page, so the click is never recorded
server-side. The SDK reports it with this endpoint (you only need it if you handle
links yourself instead of using the SDK).

```http
POST https://dynalink.app/api/links/{code}/click
```

```json
{
  "fingerprint": "102.244.220.125-Android-14-420x920",
  "source": "app_link",
  "click_ids": { "gclid": "Cj0KCQjw...", "utm_source": "google" }
}
```

Requires the `x-project-key` header. `fingerprint` is optional — when present it
uses the same `{IP}-{OS}-{Version}-{ScreenResolution}` format as the loading page,
so the click lands on the same device row as browser clicks. Repeated calls for the
same device and link within a minute are ignored (`"duplicate": true`) because the
OS can deliver the same intent more than once.

```json
{ "success": true, "clicked_count": 42, "fingerprint_id": 128 }
```

## Custom domains

A project can serve its links from its own domain (`https://links.yourbrand.com/ERTIN5`)
instead of `{projectPrefix}.dynalink.app`. Three steps:

1. Add the domain to the project (Admin Panel → Project → Settings, *allowed custom domains*).
2. Point it at DynaLink with a `CNAME` to `dynalink.app` and make sure the certificate
   covers it — DynaLink resolves the project from the request host.
3. Regenerate the App Links / Universal Links association files for that host:
   Android and Apple only ever fetch them from the host the link is served from.
   DynaLink serves them at `https://{yourdomain}/.well-known/assetlinks.json` and
   `https://{yourdomain}/.well-known/apple-app-site-association`, and the app manifest
   must list the custom domain in its `intent-filter` / `applinks:` entry as well.

A domain change takes up to five minutes to propagate.

## Link domains

```http
GET https://dynalink.app/api/projects/link-domains
```

Lists the hosts allowed to serve this project's links — its `dynalink.app`
subdomain plus any custom domain configured on the project. The SDK uses it to
recognize incoming links served from a custom domain. Requires the
`x-project-key` header.

```json
{
  "main_domain": "dynalink.app",
  "subdomain": "bailor.dynalink.app",
  "custom_domains": ["links.bailor.com"]
}
```

## Attribution

The attribution API lets you query which ad-network click IDs were captured during the browser session that led to an install or app open.

The click IDs are collected automatically by the Dynalink fingerprint page before the user is redirected to the App Store or Play Store. After the app is installed and opened, the SDK matches the device and calls the backend to confirm the attribution.

### By Fingerprint

```http
GET https://dynalink.app/api/attribution/fingerprint/{fingerprint}
```

Returns attribution data for a specific device fingerprint (`{IP}-{OS}-{Version}-{ScreenResolution}`).  
Only returns results where the install has been confirmed (`confirmed_at` is set).

### By DynaLink Code

```http
GET https://dynalink.app/api/attribution/code/{code}
```

Returns the most recent confirmed attribution for a given short code.

Both endpoints require the `x-project-key` header and return the same response shape:

```json
{
  "matched": true,
  "dyna_code": "SUMR99",
  "gclid": "Cj0KCQjw...",
  "gbraid": null,
  "fbclid": "FB.AbCdEf...",
  "fbclid_captured_at": 1716211200,
  "ttclid": null,
  "twclid": null,
  "li_fat_id": null,
  "campaign_id": 4,
  "campaign_name": "Summer 2026",
  "utm_source": "google",
  "utm_medium": "cpc",
  "utm_campaign": "summer_2026",
  "utm_term": null,
  "utm_content": null,
  "attributed_at": "2026-05-21T10:05:00Z"
}
```

If no confirmed attribution is found, the endpoint returns HTTP 404 with `{ "matched": false }`.

### Click ID Reference

| Field             | Ad Network              | How to use                                      |
|-------------------|-------------------------|-------------------------------------------------|
| `gclid`           | Google Ads              | Forward to Google Ads conversion import         |
| `gbraid`          | Google Ads (iOS 14.5+)  | Forward to Google Enhanced Conversions          |
| `fbclid`          | Meta (Facebook/Instagram) | Forward to Facebook CAPI install event        |
| `fbclid_captured_at` | Meta               | Unix timestamp — use for deduplication window   |
| `ttclid`          | TikTok                  | Forward to TikTok Events API                    |
| `twclid`          | X (Twitter)             | Forward to X Ads conversion API                 |
| `li_fat_id`       | LinkedIn                | Forward to LinkedIn Insight Tag                 |

## Webhooks

Webhooks deliver real-time HTTP `POST` notifications to your server when a DynaLink install is attributed. Each delivery is signed with HMAC-SHA256 so you can verify authenticity.

### Create a Webhook

```http
POST https://dynalink.app/api/webhooks
```

| Parameter  | Type    | Required | Description                                      |
|------------|---------|----------|--------------------------------------------------|
| `url`      | string  | Yes      | HTTPS endpoint to receive events                 |
| `events`   | array   | Yes      | List of event types (currently `install_attributed`) |
| `is_active`| boolean | No       | Enable or disable delivery (default `true`)      |

```bash
curl -X POST https://dynalink.app/api/webhooks \
  -H "Content-Type: application/json" \
  -H "x-project-key: YOUR_PROJECT_KEY" \
  -d '{
    "url": "https://yourserver.com/dynalink-webhook",
    "events": ["install_attributed"],
    "is_active": true
  }'
```

The response includes a `secret` field. **Save this value — it is only shown once.** Use it to verify incoming webhook signatures.

### Regenerate a Secret

```http
GET https://dynalink.app/api/webhooks/{id}/regenerate-secret
```

Returns a new `secret`. The old secret is immediately invalidated.

### Verifying Signatures

Every webhook delivery includes an `X-Dynalink-Signature` header containing the HMAC-SHA256 of the raw request body, signed with your webhook secret.

```javascript
const crypto = require('crypto')

function verifyWebhook(rawBody, signature, secret) {
  const expected = crypto
    .createHmac('sha256', secret)
    .update(rawBody)
    .digest('hex')
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(signature)
  )
}
```

### Webhook Payload

The payload matches the attribution API response shape:

```json
{
  "matched": true,
  "dyna_code": "SUMR99",
  "gclid": "Cj0KCQjw...",
  "fbclid": "FB.AbCdEf...",
  "fbclid_captured_at": 1716211200,
  "campaign_id": 4,
  "campaign_name": "Summer 2026",
  "utm_source": "google",
  "utm_medium": "cpc",
  "utm_campaign": "summer_2026",
  "attributed_at": "2026-05-21T10:05:00Z"
}
```

### Retry Policy

Failed deliveries (non-2xx response or timeout) are retried 3 times with exponential backoff: **60 s → 4 min → 16 min**.

## Notes

- Always include a `fallback_url` for the best cross-platform experience
- Verify `ios_bundle_id` / `android_package_name` before creating deep links with store fallback
- Keep `x-project-key` server-side whenever possible
- Webhook endpoint must respond within the HTTP timeout — offload heavy processing to a background job
